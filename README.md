# C-Home 启动页

> 自定义 Chrome 新标签页，让常用站点井井有条。

C-Home 是一个干净、现代、零依赖的 Chrome 扩展，用来替换默认新标签页。它把常用站点按分类组织在卡片网格中，并支持流畅的拖拽排序、数据导入导出与自动备份。

## 亮点

- **现代化的 UI/UX** — 玻璃拟态侧边栏、indigo/violet 渐变主色、卡片进入动画、自适应深色模式
- **FLIP 拖拽排序** — 参考 `react-beautiful-dnd` 的占位符 + FLIP 动画，拖拽时其他卡片会平滑让位，体验接近原生应用
- **跨分类整理** — 站点卡片可直接拖到侧边栏分类，自动迁移并切换目标分类视图
- **智能图标加载** — 优先获取站点 Favicon，先用本地字母头像占位，加载完成后再无缝替换，避免空白等待
- **自定义浮层提示** — 站点名称/地址过长时，hover 显示完整内容，不使用浏览器原生 title
- **导入导出与自动备份** — 支持 JSON 手动备份/恢复，自动备份可选「每次变更」「按间隔」「每日指定时间」三种策略
- **实时时钟问候** — 顶部显示当前时间、日期，并根据时段自动切换问候语
- **零外部依赖** — 纯原生 JavaScript，Chrome Extension Manifest V3

## 功能

- **站点管理**：添加、编辑、删除常用站点，自动获取站点图标
- **分类组织**：创建、重命名、删除分类；删除分类时站点自动迁移到默认分类
- **拖拽排序**：站点卡片和分类列表均可拖拽调整顺序
- **站点搜索**：在当前分类下按名称或地址搜索站点
- **深色模式**：跟随系统 `prefers-color-scheme` 自动切换
- **数据持久化**：本地使用 IndexedDB 大容量存储，可选 Chrome 同步 / WebDAV / Gist 云端，关闭页面不丢失
- **数据存储位置**：多选并存——IndexedDB 本地（大容量）、Chrome 同步、WebDAV、GitHub Gist 可任意组合，数据同时写入所有勾选位置
- **版本显示**：设置弹窗中显示当前版本号，便于排查问题

## 安装

1. 打开 Chrome，进入 `chrome://extensions`
2. 开启右上角「开发者模式」
3. 点击「加载已解压的扩展程序」，选择本项目目录
4. 打开新标签页即可使用

## 技术栈

- 纯原生 JavaScript（ES5 语法，兼容扩展环境）
- Chrome Extension Manifest V3
- CSS 变量实现亮色/深色模式
- HTML5 Drag and Drop API + FLIP 动画实现拖拽排序

## 数据说明

数据默认保存在本机 **IndexedDB**（容量可达磁盘级，远大于 `chrome.storage.local` 的 10MB），并在首次使用时请求 `navigator.storage.persist()` 持久化以避免被浏览器回收。存储位置**支持多选**，数据会同时写入所有勾选的后端，读取按 云端 -> 同步 -> 本地 优先：

- **IndexedDB 本地**：大容量，仅本机；换设备需导出备份或勾选云端后端。
- **Chrome 同步**：跟随 Google 账号跨设备，约 100KB 限制，适合小数据。
- **WebDAV 云端**：保存到你自己的 WebDAV 网盘，容量无墙、跨设备。需在设置-云端配置填写地址与凭证。
- **GitHub Gist**：轻量云备份（单文件约 1MB 限制）。需填写 Token。

可任意组合（如「IndexedDB + WebDAV」本地大容量 + 云端备份，或「IndexedDB + 同步」等）。从旧版本（`chrome.storage.local` / `sync`）升级时，会自动把旧数据迁移到当前后端，不会丢失。

云端凭证仅保存在本机 `chrome.storage.local`，不会上传。

无论使用哪种存储方式，移除扩展都会清空本地数据。建议定期通过「设置 → 导出数据」备份，或开启自动备份到下载目录。仓库内 `config/settings.json` 仅为开发参考模板，扩展运行时不读取。
